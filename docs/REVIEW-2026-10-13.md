# ASUS installation review — 13 October 2026

## Observed on the current laptop

- ASUS TUF Gaming F16 FX607VUR/FX677VU; Ubuntu 26.04.1.
- Intel GPU `8086:a7ab`, NVIDIA RTX 4050 `10de:28e1`, Intel Wi-Fi `8086:272b`.
- Intel HDA PCH / Realtek ALC256 audio.
- Ubuntu root and EFI are on the same SSD. Kernel partition geometry shows a
  roughly 146.5 GiB gap between existing partitions. A privileged `parted` preview
  is still required before writes. Do not infer contiguous space from `df`.
- A separate Windows SSD is excluded. The Ubuntu SSD also has an existing NTFS
  partition that must be preserved.
- Secure Boot disabled; about 144 GiB free inside Ubuntu before downloads.
- A TPM device exists. This does **not** establish compatibility with Google's
  Trusty/GSC security services. Saying this laptop has “no TPM” would be incorrect.

## Changes made in this local review

- USB-free copies from the original image, local boot staging, and GRUB import.
- Require installation/reset targets to be the running Ubuntu SSD; require EFI
  and boot files to stay there for GRUB setup; disable cross-disk OS probing.
- Refuse duplicate Android installs and non-512-byte logical sectors.
- Validate GPT entry CRC, geometry, overlaps, bounds, and duplicate names.
- Discover userdata by label instead of assuming partition 5.
- Check USB identity before using a GBOS-ESP label.
- Make core104/core105-to-core103 firmware aliases explicit and opt-in; never overwrite genuine firmware.
- Verify the entire rebuilt vendor image after writing and check its extent size.
- Require confirmation before vendor/signing writes; discard failed EROFS builds.
- Default custom-key boot reporting to yellow, not manufacturer's green.
- Check the recovery checksum; prefer installed AOSP lpunpack, otherwise use a
  commit-pinned, SHA-256-checked third-party implementation.
- Add disk-free regression coverage to CI.

## Original Google/AOSP components versus adaptations

| Component | Assessment |
|---|---|
| Google recovery OS, apps, kernel, ramdisks | Keep the original pinned Google download. System/product images are retained by the vendor patcher. |
| Graphics compositor / allocator | The bare-metal vendor script already keeps the stock graphics stack. Cuttlefish graphics files are extracted but not substituted by this script. |
| KeyMint and Gatekeeper | Existing replacements come from Google's AOSP Cuttlefish build. They are official test components, but software implementations do not provide hardware-backed security. Restoring incompatible stock services is not a fix. |
| Boot-control HAL | AOSP Cuttlefish replacement; keep until a native compatible HAL has been demonstrated. |
| Intel Wi-Fi/Bluetooth/GPU firmware | Use genuine files under their upstream filenames. Firmware is hardware-vendor software, not something Google-branded software can replace. |
| Audio | Stock audio stack with ASUS HDA configuration changes. Keep these until the unmodified Google audio configuration supports this exact codec/card. |
| Image unpacker | Prefer AOSP's lpunpack host binary when available. Pinned Python fallback remains for practical installation. |
| AOSP avbtool | Already the official AOSP implementation. Custom signing cannot recreate Google's manufacturer keys or hardware attestation. |
| Google Device Recovery Utility | Official recovery for supported Googlebooks. It does not document installing on this ASUS gaming laptop; stock recovery can erase the whole target drive. Do not use it on either internal SSD here. |
| ChromeOS Flex | Official Google PC OS alternative, but a different product with different Android/Play support. It is not a drop-in replacement for this Googlebook installation. |

Official references:

## Remaining work and limits

This is not a claim that everything works. First-boot testing remains necessary.
The repo's prior hardware results are reports, not tests repeated in this review.

1. Completed: recovery MD5 and Cuttlefish SHA-256 match the pinned builds; both
   images unpacked. Extracted logical partition sizes match LP metadata. The staged
   bootconfig checksum and GRUB syntax validate. All 27 disk-free regression tests,
   ShellCheck error checks, shell syntax and Python compilation checks pass.
   The privileged BUILD_ONLY vendor build passed SELinux CIL compilation and
   produced a 363,036,672-byte filesystem fitting its 380,608,512-byte slot;
   fsck.erofs passed. No target partitions were written by that build.
2. Completed: privileged dry-run selects Ubuntu SSD by serial. Replayed the exact
   32-partition plan on a sparse test image: all new extents lie inside sectors
   324374528..631574527, the existing four GPT entries are byte-for-byte unchanged,
   and sgdisk verification passes. Planned span is 58.07 GiB of a 146.48 GiB gap.
   Installation and boot subsequently succeeded; vendor writes passed full read-back.
3. Boot and test the hardware checklist in USB-FREE.md.
4. Investigate phone integration from actual Android logs. Do not spoof attestation
   or promise that reporting a locked state will enable Google services.
5. Design an update strategy: stock OTA updates may replace patched vendor data
   or assume the original partition/boot layout. Updates are not validated.
6. Full Secure Boot requires a verified chain from firmware through GRUB, kernel,
   ramdisk and Android. A bootconfig property is not such a chain.
7. Dynamic-partition parsing, power-loss recovery, reruns after interrupted
   extraction, and all optional maintenance scripts deserve further testing.
